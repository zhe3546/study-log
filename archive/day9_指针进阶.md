## 1. 三秒回顾:指针的三个写法

```c
int a = 10;
int *p = &a;
```

- `p` → 地址(纸条上的门牌号)
- `*p` → 那个地址里的值(10),和 `a` 是同一个房间的两种叫法
- `&a` → a 的地址

今天在这个基础上加两件事:**指针怎么和数组配合**,**指针怎么让函数改到外面的变量**。

---

## 2. 关键事实:数组名就是首元素的地址

这句话是今天的第一块基石,先做实验验证:

```c
int a[5] = {1, 2, 3, 4, 5};
printf("%p\n", a);        // 0x...A20
printf("%p\n", &a[0]);    // 0x...A20  完全一样!
```

**`a` 和 `&a[0]` 打印出同一个地址**——数组名 `a` 本身就是"第 0 个元素的地址"。

由此推出一个等价关系(重要,考研常考):

```c
a[i]  等价于  *(a + i)
```

`a + i` = 从第 0 个往后数 i 格的地址,`*` 取那个地址里的值。所以 **`a[2]` 只是 `*(a+2)` 的简写(语法糖)**,机器眼里根本没有"下标"这个动作。

## 3. 指针运算:`p + 1` 跳多远?(今天最反直觉的地方)

```c
int a[5] = {1, 2, 3, 4, 5};
int *p = a;
printf("%p\n", p);       // 0x...A20
printf("%p\n", p + 1);   // 0x...A24  注意!差了 4,不是 1
```

**`p + 1` 不是"地址加 1",而是"往后跳一个元素"**——int 占 4 字节,所以跳 4 个字节。如果 p 是 `char *`(1 字节),`p+1` 就只跳 1 字节。

**为什么必须这样设计?** 因为 `p+1` 的用途就是"走到下一个元素"。如果它只加 1 个字节,你就落在了某个 int 的中间,取出来的会是半个数字拼成的垃圾。所以规则是:

> **指针 +/- 整数 n,实际地址变化 = n × sizeof(指向的类型)**。

这就是"指针必须有类型"的原因(`int *p` 而不是 `void *p`):类型告诉编译器**一步该跨多远**。

**自测**:`double a[3]; double *p = a;` 那么 `p + 2` 比 `p` 的地址大多少字节?(答案:16)

## 4. 用指针遍历数组(两种方式都写一遍)

**方式一:下标法(你熟的)**
```c
for (int i = 0; i < 5; i++)
    printf("%d ", a[i]);
```

**方式二:指针移动法(今天的)**
```c
for (int *p = a; p < a + 5; p++)     // p 从首元素出发,每轮走一格,直到越过末尾
    printf("%d ", *p);
```

- `p = a`:p 指向第 0 个元素;
- `p++`:走到下一个元素(自动跨 4 字节);
- `p < a + 5`:结束条件,`a+5` 是"第 5 个(不存在的)元素的地址",即数组末尾之后一格——**这个位置不能取值,只能用来比较**,和下标写法的 `i < 5` 是同一件事。

⚠️ 注意:`p++` 移动的是 p,**不是移动数组**。`a++` 是非法的(数组名是常量地址,不能改)。

## 5. 揭晓思考题:为什么 bubbleSort 能改到 main 的数组

```c
void bubbleSort(int a[], int n) { ... }   // 函数里排序
bubbleSort(s, 10);                        // main 里的 s 真的变了
```

**答案**:函数参数写 `int a[]` 时,编译器根本不会复制一份数组(那太浪费内存),它实际传的是**数组首元素的地址**——等价于 `int *a`。所以函数内部操作的 `a[i]`,就是 main 里那块内存。

一个验证实验(有点超纲但很有意思):

```c
void f(int a[]) {
    printf("%zu\n", sizeof(a));   // 8 —— 它不是数组了,是指针(64 位系统指针占 8 字节)
}
int main(void) {
    int s[10];
    printf("%zu\n", sizeof(s));   // 40 —— 真数组,10 个 int × 4 字节
}
```

**这也解释了为什么数组做参数时,必须额外传一个长度 n**——函数里已经不知道数组多长了。

## 6. 值传递 vs 地址传递:全月最经典的考题

看这两个函数,一个白干一个生效:

```c
// ❌ 失败版
void swap(int x, int y) {
    int t = x; x = y; y = t;      // 改的是自己房间里的副本
}
// ✅ 生效版
void swap(int *x, int *y) {
    int t = *x; *x = *y; *y = t;  // 按地址找到原件,直接改
}
```

**为什么失败版不行?**

调用 `swap(a, b)` 时,系统做的是:**把 a 的值复制一份放进 x,把 b 的值复制一份放进 y**。x 和 y 是函数自己的新房间(叫形参),里面装的是复印件。你在函数里把 x、y 换来换去,main 里的 a、b **毫发无损**;函数结束,x、y 房间被回收,没有留下任何痕迹。

**一句话记住**:
> **传值 = 给你复印件,复印件改破天,原件不动;传地址 = 告诉我原件在哪,我直接改原件。**

所以正确的 swap 要这样用:

```c
int a = 3, b = 5;
swap(&a, &b);        // 注意:传的是地址,所以前面加 &
printf("%d %d\n", a, b);   // 5 3  交换成功
```

**这就是你 Day 2 学到的 `scanf("%d", &a)` 的同一个道理**——凡是"要让函数改动外面的变量",都必须把地址交出去。看到这里的规律了吗?**`&` 出现的场景只有一种:需要改外面,就得给地址。**
